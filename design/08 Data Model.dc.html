Conventions

· ids are ULIDs (time-sortable, opaque); every table has created_at, updated_at, and tenant_id where the row belongs to a merchant — row-level security keys on it.
· money is bigint cents in CAD; never floats. Tax is stored per line as computed at checkout.
· i18n user-facing text lives in *_i18n jsonb keyed by locale ({"en-CA":…,"fr-CA":…}) with the source locale marked; UI strings live in i18n.translations.
· geo uses PostGIS geography(Point/Polygon,4326) with GiST indexes; zone membership is precomputed onto addresses.
· state machines are Postgres enums with a companion *_events table (append-only) so every transition is auditable and replayable.
· outbox: every schema has an outbox table written in the same transaction; Debezium streams it to Kafka. Consumers are idempotent on event_id.
· soft delete via deleted_at for anything a customer can see; hard delete only through the privacy-erasure job (PIPEDA).
· migrations: Flyway, expand/contract; no destructive change in the same release as the code that stops using a column.

Where search comes in

Postgres is the source of truth and is never queried for search. The search-indexer consumes listing.*, availability.*, merchant.* and food.item_* events from Kafka, joins the read model and writes three OpenSearch indices: listings (offers + services + menu items, denormalised with merchant tier, geo point, price, next available slot, dietary/allergen tags, fr/en fields), merchants, and suggest (completion suggester with per-language synonyms — pain au levain → sourdough). Queries filter by geo_distance to the customer's zone and apply function_score boosts for trust tier, distance, "on tonight's run" and personal history. Hot queries cache in Redis for 30 s; reindexing builds a new index and swaps the alias. Target p95 < 250 ms.
