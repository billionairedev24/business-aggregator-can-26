# Northline — agent instructions

You are implementing the Northline marketplace from a finished design spec. **Do not deviate from the spec.** Where it is silent, choose the simplest option consistent with it and record it in `docs/DECISIONS.md`.

## Source of truth (priority order)
1. `db/migrations/*.sql` — schema (V001–V017). Column names and enums are final.
2. `docs/spec/` — machine-readable rules (legal-details schema, storefront sections, validation messages) + `db/seed/categories.json`.
3. `docs/ARCHITECTURE.md`, `docs/DATA_MODEL.md` — modules, events, flows.
4. `design/*.dc.html` — interactive references of every screen (open in a browser). Behavioural spec for copy, states, ordering. Recreate, don't copy. **Their look is retired** (2026-10-18): layouts, visual language and the screen-by-screen look come from `docs/design/redesign-spec.md`.
5. `design/09 Terms of Service`, `design/10 Privacy Policy` — ship verbatim; open from registration in a new tab.

## Stack (fixed)
- **Backend:** Java 25, Spring Boot 4.1.1, Spring Modulith 2 — `server/api` (modular monolith, one package + schema per module), `server/auth` (Spring Authorization Server, OAuth 2.1/OIDC, passkeys, TOTP, Google/Apple), `server/bff` (Spring Cloud Gateway MVC, token relay, Redis session), `server/worker` (Kafka consumers: search indexer, notifications, webhooks). Virtual threads on.
- **Data:** PostgreSQL 17 + PostGIS (Flyway), Elasticsearch 9 (search read model only), Redis 8 (sessions, cache, rate limits, idempotency, slot holds, live tracking pub/sub), Kafka 4 (KRaft).
- **Events:** publish with `ApplicationEventPublisher` inside the state-changing transaction; Modulith JDBC registry is the outbox (`events.event_publication`); cross-module listeners are `@ApplicationModuleListener`; `@Externalized` events go to Kafka topic `<module>.<aggregate>`, key = aggregate id. Consumers dedupe via `events.processed_events`, `@RetryableTopic` → `.dlq`. JSON Schemas in `server/api/src/main/resources/events`; breaking change = version bump.
- **Frontend:** pnpm monorepo `web/`. TanStack Start + Router + Query + Form + Table + Virtual, React 19, TypeScript, zod. `packages/ui` holds every component, each with a Storybook 9 story (a11y addon must pass). `packages/tokens/brand.json` (+ its palette in `packages/tokens/palettes/`) is the ONLY place colours/fonts/radii and the product's name are defined — components use semantic `var(--color-*)` tokens only; no hex literals in components (lint rule), no literal product name in UI strings (`{brand}` / `brand.name`, lint rule).
- **Payments:** Stripe Connect Express, manual capture (escrow), Stripe Tax. **Residency:** ca-central-1.
- Bilingual en/fr from day one.

## Design system — E-15 Full UI revamp, tokens v2 and @northline/ui (S-167/S-168; `docs/design/revamp-epic.md`, mockups `design/revamp/a.html`)
- **The locked direction is A · Plainsight** with Main Street's maker-of-the-week hero on the consumer home. **When a story and the mockups disagree, the mockups win.** Page layouts are S-170+; the system below is built.
- **The brand is one file:** `web/packages/tokens/brand.json` (name and identity, `palette`, `chrome`) + `palettes/<palette>.json`. The default is `plainsight`; lakeshore, evergreen and dusk still build. A palette has `color` (what the derivation and the email copy read), `roles` (semantic roles pinned to the mockups' exact values), `radius` and `shadow`, `font`, `mark`. `pnpm --filter @northline/tokens build` regenerates `generated/theme.json` (committed; TypeScript, the email test and the native apps read it; then `pnpm --filter @northline/mobile-kit brand`) and `dist/tokens.css`, and **fails when any pair of any palette drops below WCAG AA**. `scale.json` (not brand) holds spacing (incl. `--space-1-5/2-5/3-5`), the type roles `--type-*` (page-title 24, section 18, sub 16, card-title 13.5, body 14, label 13, meta 12, caps 11, price*) and `--density-*`.
- **Colour roles, one role per colour:** `--color-action-primary` (Add to cart, Book, Place order, links) · `--color-selected*` (segments, chips, tabs, checkboxes, the current page: solid ink; `selected-tint` for an applied chip) · `--color-commerce*` (deals, the cart count, the cut-off — never a button) · `--color-status-{success,warning,danger,info,neutral}-{fg,bg}` (status tags) · `--color-well*` (photo wells, strips, empty states) · `--color-border` / `border-strong` hairlines, `border-control` the 3:1 outline · `--color-star`, `--color-price`. The action colour is never a status; destructive actions are `btn-destructive` (red). Older names (`--color-accent*`, `--color-highlight*`, `--color-neutral-*`, `--color-bg`, `--font-body`) are deprecated aliases kept out of `@northline/ui` and the shells by `pnpm lint:tokens`.
- **Shape and type:** 3 px corners on controls (`--radius-control`), 4 px on panels (`--radius-panel`), `--radius-round` only for what is a circle; `--radius-pill` is 3 px in Plainsight — **never pills**. IBM Plex Sans (self-hosted from `@fontsource`; the CSPs allow `'self'` only) for all text and every heading — no serif, no display face. Phosphor icons.
- **Components (`@northline/ui`):** buttons `primary | secondary | tertiary | destructive` (+ `dark`), drawn 38 px with a 44 px hit area; `UnderlineTabs` (with counts) is the one tab style (`ChipTabs` draw as it); `Segmented` (joined boxes; `size="sm"`, `fill`); `Chip` / `FilterChip` (square, applied = ink edge on the tint + ✓, removable ×); `ChoiceTiles`, `OptionCard` (`mark`), `Checkbox` (`count`), `Switch`; `SearchBar` (`scope` = department select); `Field`/`TextInput`/`Select`; `Price` (the one format `$8.50` / `8,50 $` + unit price; never format prices by hand), `Stars`, `DealBadge`, `StatusTag`, `ProductCard` (product on white in a 1:1 grey well, dashed fallback with the category icon), `ServiceCard`, `QuantityStepper`; `SiteHeader` + `PromoStrip` (the consumer header, strip and cut-off line), `FilterGroup` + `RatingFilter` (a results rail), `PanelTile` + `PictureGrid` (home tiles), `.nl-card-grid-results` (5 a row), `unitPriceOf` (the unit price a pack's words state); `DataTable`, `Dialog` (`sheetOnPhone`), `Drawer`, `Toast`/`useToast`, `Pagination`, `EmptyState`, `Skeleton`/`CardSkeleton`, `PageHeader`, `Alert`. Back office (S-174): `AppShell` (white top bar with `WorkspaceSwitcher` and `ShellSearch` — "/" focuses it —, grouped sidebar, icon rail < 1024 px, disclosure menu < 768 px), `ActionGrid`/`ActionCard` ("Needs you now": job, deadline, one button, urgency edge), `KpiStrip`, `ColumnChart`, `SummaryTable` + `Thumb`, `ChartCard`. **Every choice shows its selected state** for aria-pressed, aria-selected, aria-checked, a checked input and data-state alike. Dates: `formatWhen` / `formatTimeRange` / `formatDateRange` — never an ISO string on screen. Record pages (S-177): `RecordHeader` (status + key facts), `RecordLayout` + `ActionPanel`/`ActionPanelItem` (the right-hand panel), `RecordTabs`, `RecordHistory`; `DataTable` `tabs` (a caller's tabs, e.g. api counts) · `filters` (a toolbar slot) · `dense` · `status-*` tones; KPI money `formatCompactMoney`.
- **Native kit (`@northline/mobile-kit`, S-169):** the consumer and courier apps share one kit on the same tokens (`mobile/packages/mobile-kit/src/ui/kit`): `Button` (`primary | secondary | tertiary | destructive | dark`, `sm` 32 + slop · `md` 44 · `lg` 46), `IconButton`, `UnderlineTabs`, `Segmented` (`stack`, `fill`, `role="tab"`), `FilterChip`, `ChoiceTiles`, `OptionCard`, `Checkbox`, `Switch`, `PhotoWell`, `ProductCard`, `ServiceCard`, `Price` + `formatPrice` / `formatUnitPrice` / `formatTimeRange` / `formatDateRange`, `Rating`, `DealBadge`, `StatusTag`, `CountBadge`, `QuantityStepper`, `TextField`, `SearchBar` (department scope in a sheet), `BottomSheet`, `Toast`/`useToast`, `EmptyState`, `Skeleton`/`CardSkeleton`, `AppHeader`, `BottomTabBar`; text roles `textStyles`. The apps' own primitives (`consumer/src/ui/*`, `courier/src/components/ui.tsx`) wrap it. Circles use `radius.round`, never `radius.pill` (tests refuse it); the kit's rules test refuses raw colours, sizes, spacing and radii. Gallery: `/dev/gallery` in a dev or fixture build of either app (`make mobile-shots` photographs it). **Screens (S-178/S-179)** use only the kit's roles, scale and components: `mobile-kit/src/ui/kit/rules.ts` (run by both apps' conventions tests) refuses raw colours, font sizes, line heights, spacing and radii, the display face, `surface-sunken`, older radius names, drawn `Scene`s, hand-made currency formats and React Native's `Switch`; pictures are a library photo in the grey well or the dashed fallback (consumer `Picture`, kit `PhotoWell`), prices `formatPrice`/`Price`, windows `formatTimeRange`. Don't re-style a library class from app CSS to change its look — change the component (layout overrides are fine). The product's name: messages say `{brand}`, code says `brand.name`, the mark is `<Logo/>`; `pnpm lint:brand` fails on the literal; don't rename `@northline/*` packages until the name is chosen.
- **Look at it:** the gallery (`pnpm dev:gallery`, `web/apps/gallery`, every component in en/fr-CA; Storybook "Gallery" shows the same) and `pnpm test:visual` (`make ui-visual`; `UI_VISUAL_UPDATE=1` rewrites the baselines after an intended change, commit them with it). ## Non-negotiables
- Every rule in `docs/spec/validation-rules.md` exists on client (zod) AND server (Bean Validation) with the exact messages.
- DB triggers in V016 (category limits, principal ownership, quote totals, sections) are never bypassed.
- Quotes are itemized and versioned; customers see every line, scope, exclusions, warranty, deposit, validity.
- No off-platform payments. Escrow release: services 48 h after completion, goods 7 days after delivery, food on handoff.
- Browsers never see OAuth tokens (BFF). Business + staff tokens require `acr=mfa`.
- No PII in event payloads. Never store SIN or card numbers.

## Working order
1. `docker compose --profile all up -d` (or only the stand-ins you lack — `docs/runbooks/local.md`) → `./gradlew :api:flywayMigrate` → seed categories (topics are created by the compose `events` profile).
2. auth (register/sign-in/passkey/MFA, "Not you?", sign-out) → bff → identity → merchants onboarding → catalogue/food → search indexer → booking (quotes) → payments (escrow) → orders/fulfilment → the rest.
3. `pnpm i && pnpm storybook` — build components in Storybook first, then routes in `apps/consumer`, then studio and console apps.
4. For each screen: layout and look from `docs/design/redesign-spec.md` § 2 (its AfroTransact reference); states, copy and behaviour from the matching `design/*.dc.html`.

## Code standards
Mandatory — see `docs/ARCHITECTURE.md` § Code standards: proper encapsulation, abstraction and interfaces; Java 25 language features; Go 1.26 for any Go app; Lombok; no boilerplate.

## Conventions
- IDs ULID text. Money `*_cents bigint` CAD. Time `timestamptz`, displayed in the merchant's or market's time zone from the region model (S-134, docs/runbooks/regions.md) — never a province, city or zone in code (lint).
- REST + OpenAPI 3.1 under `/api/v1`. Idempotency-Key header on money-moving POSTs (stored in Redis 24 h).
- Tests: `ModularityTests` must pass; every trigger has a failing-case test; every validation rule has a message test; Testcontainers for Postgres/Kafka/ES; Storybook interaction tests for every component state.

## Branches
`develop` is the integration branch: branch from it and open every pull request against it. `main` is releases only (a `develop` → `main` pull request). Never push to either directly.
