# UI audit, October 2026 (S-165)

**Date:** 2026-10-23. **How:** `make ui-shots` production builds of consumer web, Studio and console against the mock
API, 125 routes at 1440 and 390 wide. A browser probe on every route checked console errors, CSP, font loading and
broken images. Studio and console were served with the real nginx CSP. The mobile apps were not captured; they are
covered in S-178/S-179.

## Verdict
The problem is mainly **direction and content** (photography, type, pill-everything, colour roles), then the
**component system** (selection states, tokens bypassed, formatting). Page layout is a minor factor, and deploy is fine.
E-15 therefore starts with the direction (S-166) and photography (S-181) before any page work.

## Deploy and build: not broken
- Fraunces and DM Sans load on 125 of 125 routes, token CSS applies everywhere, with 0 CSP violations and 0 broken images.
- The Helm chart sets no CSP. Dev and production renders of the home page are pixel-identical. No page scrolls
  sideways.
- One real bug: a React hydration mismatch (#418) on `/shop`, `/shop/bakery` and the provider page, probably from
  time-based text (`ago()`, `Date.now()`) rendered on the server (S-182).

## Problems, ranked
1. **Photography.**
   - Demo listings use 1024px amateur photos, which look blurry when stretched in banners.
   - 58 of 162 categories have no photo, so `/services` repeats the same image up to 6 times in a row.
   - The sign-in hero shows a US flag on a Canadian product.
2. **Screenshots don't match the demo.** `ui-shots` draws clean SVG illustrations, while `make demo-data` uploads the
   photos above, and items without a photo get a drawn PNG of their name. Reviews have been done on nicer pages than
   the owner sees (S-182).
3. **Selected choices are invisible.** Single-choice chips (checkout tip and substitution, Aftercare, the Studio
   button-label picker) show no selected state. `primitives.css:42` only styles `aria-pressed` / `aria-selected`.
4. **Everything is a pill.** Buttons, tabs, filters, segmented controls and pagination look alike, and at least four
   tab styles are in use. A selected tab reads as a primary button.
5. **Serif everywhere.** Fraunces is on every h1–h3, back-office panel titles included, against the spec's own rule
   (one sans for UI, the serif for marketing only).
6. **Loose colour roles.** The accent is used for buttons, chart series and status. Destructive actions (Suspend) are
   brand green. Every status chip is the same grey.
7. **Tokens bypassed.**
   - About 470 spacing values are off the 4-pt scale; the Studio uses more raw px than spacing tokens.
   - There are about 240 raw font sizes and about 180 inline `style` objects.
   - App CSS overrides `@northline/ui` classes 38 times.
   - Lint checks only colours and the brand name.
8. **Formatting.** Three price styles appear on the same pages, and raw ISO date ranges reach the orders page.
9. **Desktop space.** The account grid leaves a dead right column, sign-in has a wide empty gap, and the footer is
   about 400px tall on every page.
10. **Studio storefront preview.** It still uses the old dark-green look, which doesn't match the real provider page.
